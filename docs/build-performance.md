# Web build performance

This note records the lazy-import split of the web bundle as a historical
measurement, then the current state of the same build. Build timings are
single-run samples for direction, not a benchmark contract; run
`pnpm --filter @app/web build` for fresh numbers.

Dev launcher: `pnpm dev` runs the HMR workflow via `scripts/dev-hmr.mjs` and
does not build the web app (Vite serves the browser bundle). The build-first
workflow is `pnpm dev:build`; `pnpm build` produces both build artifacts
without starting a server. The measurements below come from a
`pnpm --filter @app/web build` in the build-first path.

## Historical measurement (2026-08-16)

The web build is the first build step run by the build-first workflow. These
measurements use the checkout's locked toolchain: Node 22.22.3, pnpm 9.15.9,
and Vite 7.3.6. The pnpm store was warm; each build started with a clean
`apps/web/dist`.

## Before and after

The baseline was captured before the lazy imports were added. The final build
uses the same command, but skips Vite's per-asset gzip reporting and measures
compression separately when needed. Timings are single-run samples, so they
are useful for direction rather than as a benchmark contract.

| Measurement | Before | After |
| --- | ---: | ---: |
| Modules transformed | 2,242 | 2,244 |
| Largest JavaScript chunk | `index` 628.07 kB, 197.83 kB gzip | `index` 376.08 kB, 117.15 kB gzip |
| Vite chunk warning | emitted | none |
| Vite reported build time | 3.47 s | 3.37 s |
| Shell elapsed time | 4.55 s | 4.29 s |

The after gzip value in the table comes from a build with Vite compression
reporting enabled during analysis. Normal builds set
`build.reportCompressedSize: false`; a gzip-9 pass over the final JavaScript
assets measured the main chunk at 116.98 kB. Skipping the report avoids a
full compression pass on every build. A split build with compression reporting
still enabled took 3.77 s in the same session, so this is a low-risk build-time
saving, not a warning suppression.

## Current state (rebuilt 2026-08-19)

Rebuilt from a clean `apps/web/dist` with the same locked toolchain. The
application entry has grown back above Vite's default 500 kB threshold, so the
chunk-size warning is emitted again. No `chunkSizeWarningLimit` change or
manual warning exemption has been made; reducing the entry chunk is future work
if the warning matters.

| Measurement | 2026-08-19 (single sample) |
| --- | ---: |
| Largest JavaScript chunk | `index-FqehP-Jw.js` 518.29 kB |
| Vite chunk warning | emitted |
| Vite reported build time | 3.63 s |
| Shell elapsed time | about 5.6 s |
| Encoder worker | 169.63 kB (lazy, unchanged) |

The lazy split shape is intact: session routes, settings, export, and dialog
chunks are still deferred (for example `SessionIndex` 16.42 kB,
`SettingsDialog` 101.86 kB, `StoppedSession` 4.07 kB), so only the shared
application entry is above 500 kB.

## Bundle composition

A temporary `vite build --sourcemap` was used to attribute generated bytes to
source modules. Source maps are not enabled in the normal build.

The original 628.07 kB entry was dominated by:

- `react-dom` production client: about 176.9 kB
- `tailwind-merge`: about 27.4 kB
- `session/websocket-transport.ts`: about 18.9 kB
- `App.tsx`: about 15.2 kB
- `session/controller.ts`: about 12.1 kB
- React Router and the remaining React runtime: about 30 kB combined
- Eager UI/session modules, including `SessionScreen`, `Readiness`, and
  `SettingsDialog`, made up the remaining large tail.

The final output keeps the session/runtime entry below the warning threshold
and defers UI that is not needed for the first screen:

| Asset role | Minified size | Loaded when |
| --- | ---: | --- |
| Shared application entry | 376.08 kB | application startup |
| Session index route | 15.37 kB | `/` route |
| Live session screen | 41.21 kB | live session route |
| Settings dialog | 89.06 kB | settings is opened |
| Export popover | 26.16 kB | session index/export UI |
| Base UI shared chunk | 76.80 kB | a dependent UI chunk is loaded |
| Encoder worker | 169.63 kB | recording encoder use |

The largest deferred chunks are also below 500 kB. The encoder worker was
already separate and is mostly `@breezystack/lamejs` (about 168.8 kB); it is not
part of the application entry.

## Implementation and validation

`App.tsx` now lazy-loads `SessionIndex`, `SessionScreen`, `StoppedSession`, and
`SettingsDialog`, with a loading fallback around each route boundary. Header
appearance/settings controls live in `settings/SettingsControls.tsx`, so the
settings dialog's Base UI dependencies are not pulled into the header's eager
path.

No `chunkSizeWarningLimit` change or manual warning exemption was made.

Validated with:

- `pnpm --filter @app/web typecheck`
- `pnpm --filter @app/web test` (24 files, 175 tests)
- `pnpm --filter @app/web build` (no chunk-size warning)
- Standalone Vite `fake-services` browser smoke (home route and lazy settings
  dialog)

The targeted Playwright route/settings suite was also attempted, but its host
sidecar could not start in this checkout because `.venv/bin/python` is absent;
that environment issue occurs before the browser reaches the web app.
